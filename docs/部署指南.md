# 部署指南 —— 前端 Vercel + 后端 Railway

> 目标拓扑：
>
> ```
> 评委浏览器
>    │  https://<vercel 域名>        （前端 React 产物）
>    ▼
> Vercel 前端 ── /api ──▶ Railway 后端（FastAPI，托管 frontend/dist 之外的接口）
>                              │ 挂载 Volume → backend/data（报告/账号/演示库持久）
>                              ▼
>                      DeepSeek API（仅自由提问/AI 兜底）
> ```
>
> 后端 CORS 放行 Vercel 域名（`MEDGUARD_CORS_ORIGINS`）；前端请求走
> `VITE_API_BASE` 指向 Railway 地址。两者都必须配置，缺一个就是 401/跨域。

---

## 〇、前置条件

- 仓库已推到 GitHub（本仓库 `git\MedGuard`）
- 两个平台账号：Vercel（https://vercel.com）、Railway（https://railway.app）
- DeepSeek API Key（`OPENAI_API_KEY`）

---

## 一、Railway —— 后端（先做，前端要它的地址）

1. **导入仓库**：Railway 控制台 → `New Project` → `Deploy from GitHub repo` → 选本仓库。
   （仓库根有 `railway.toml` + `Procfile`，Railway 会自动采用：Nixpacks 构建 Python、
   启动命令 `cd backend && uvicorn … --port $PORT`、健康检查 `/api/health`。）
2. **挂数据卷**（关键，否则重启丢数据）：Deploy 后进入该 Service → `Settings` →
   `Volumes` → `Add Volume` → 挂载路径填 **`/app/backend/data`**（与 `railway.toml`
   的 `[[mounts]]` 一致；新项目会按 toml 提示创建）。
3. **环境变量**（Settings → Variables）：

   | 变量 | 值 |
   |---|---|
   | `OPENAI_API_KEY` | 你的 DeepSeek Key |
   | `OPENAI_API_BASE` | `https://api.deepseek.com/v1` |
   | `MODEL_NAME` | `deepseek-v4-flash` |
   | `MEDGUARD_CORS_ORIGINS` | `https://<你的vercel域名>`（下一步拿到后回填） |
   | `MEDGUARD_TOKEN_SECRET` | （可选）任意长随机串；不设则自动生成并存进 data 卷 |

   注：`.env` 被 gitignore 排除、不进仓库，Key 只从这里注入。
4. **等部署完成**，记下生成的域名：`https://medguard-production-xxxx.up.railway.app`。
5. **验证**：浏览器开 `https://<railway域名>/api/health`，应返回
   `{"status":"ok","algo_engine":"available",…}`（首次启动自动建演示库）。

---

## 二、Vercel —— 前端

1. **导入仓库**：Vercel 控制台 → `Add New Project` → 导入同一个 GitHub 仓库。
2. **框架识别**：自动识别 Vite（无需改构建设置；构建命令 `tsc -b && vite build`，
   输出目录 `dist`）。
3. **环境变量**（Settings → Environment Variables）：

   | 变量 | 值 |
   |---|---|
   | `VITE_API_BASE` | `https://<railway域名>`（上一步的地址，不带末尾斜杠） |

   > Vite 在**构建时**注入该变量，改完需 Redeploy。
4. **Deploy**，得到 `https://medguard-xxxx.vercel.app`。
5. **回填 CORS**：把该域名填回 Railway 的 `MEDGUARD_CORS_ORIGINS`
   （逗号分隔可放多个，如 `https://medguard-xxxx.vercel.app,http://localhost:5173`），
   Railway 会自动重启生效。

## 三、验收清单（部署后逐条过）

- [ ] `https://<vercel域名>` 打开登录页，三个账号（admin/doctor/patient，口令 medguard）能登录
- [ ] 患者 → 智慧医生：点「帮我看懂检查报告」出现三块+来源标注（**数据来自 Railway 的演示库**）
- [ ] 患者 → 「得这个病的有多少人」→ 层一拒绝固定文案

- [ ] 安全报告页能列历史、导出 JSON
- [ ] **重启后端一次**：报告/账号还在（Volume 生效）

## 四、常见问题

| 现象 | 原因与处理 |
|---|---|
| 前端 401「令牌缺少签名或有效期」 | `VITE_API_BASE` 没配/配错，请求打到了别处；核对两处域名 |
| 跨域报错（CORS） | Railway 的 `MEDGUARD_CORS_ORIGINS` 没填 Vercel 域名或没重启 |
| 登录 503「平台元数据库尚未初始化」 | Volume 没挂（每次都重建）；挂载 `/app/backend/data` 后 Redeploy |
| 前端请求提示"无法连接后端服务" | 后端没起/域名过期；`https://<railway域名>/api/health` 直接开 |
| 自由提问一直失败 | 看 Railway 日志；`OPENAI_API_KEY` 未设或无效 |

## 五、本地与线上共存

- 本地演示不受影响：`start_demo.bat` 同源托管，`VITE_API_BASE` 留空即相对路径。
- 两者是同一份代码、同一份配置开关（`MEDGUARD_CORS_ORIGINS` / `VITE_API_BASE`），
  不在控制台设环境变量时行为与现在完全一致。
