# MedGuard RAG 调研后的适配建议

日期：2026-11-15。范围：本机 `C:/Users/lwh/Desktop/git/MedGuard` 当前文件；不是线上运行验证。本文记录调研与代码检查，没有修改应用代码，也没有运行付费模型评测。

## 结论与证据等级

推荐保留结构化直接查询，并把现有 BGE + BM25 + RRF 扩展成按问题选择路径、按字段组织证据的混合检索。不能因方法较新、论文分数较高或存在产品文档，就宣称在本项目更优。下文区分官方公开方法、代码观察和拟实施建议；所有性能与质量提升都需本项目对照实验验证。

并非每条数据都应向量化，也并非每次取数都应调用生成模型。SQL、按实体 ID 查 JSON、图邻接查询同样可以向模型提供证据；在广义上属于结构化检索增强。业务上应区分“取到可信数据”“检索非结构化证据”“生成解释”三个步骤。

## 本地代码观察

- `backend/backend/smart_doctor.py:270`：确定性意图路由；主要返回单个实体，尚不适合直接表达两个疾病的比较意图。
- `backend/backend/dataset_kb.py:118`：疾病先精确命中，再双向包含匹配。纯本地补测：`1型糖尿病`、`2型糖尿病`、`一型糖尿病`、`二型糖尿病`均返回`糖尿病`。若需求要求子型差异，泛疾病事实不足以支持回答。
- `backend/backend/smart_doctor.py:989` 和 `:1063`：检查/用药走统一审计执行通道，读取本人业务记录，然后用 YAML 解释；这两条分支未调用 `_ai_explain`。
- `backend/backend/smart_doctor.py:1129` 和 `:1187`：症状/疾病先查 OpenCMKG 派生表，命中后可调用模型改写。因此“查表离线”不等于“整轮回答离线”。
- `backend/backend/smart_doctor.py:601`：RAG 返回的 `Doc.text` 被直接放入证据列表。`knowledge/opencmkg.py` 注释说应回查完整事实卡，但这个业务路径没有实现该回查。
- `backend/backend/knowledge/corpus.py:141`：YAML 五类资料一起展平成语料；症状和疾病字段仍进入 RAG。YAML 文件头“这些字段不再读取”的表述不适用于检索分支。
- `backend/backend/knowledge/hybrid.py:338`：混合召回后做 RRF，有来源权重与核心资料保留规则；没有根据用户问的是检查/病因/对比来做证据字段过滤。RRF 分数是排名融合结果，不是医学置信概率。
- `backend/backend/knowledge/hybrid.py:114`：已有 NumPy 矩阵检索及磁盘缓存，应保留，不能继续把历史 Python 逐条余弦的旧实测作为当前延迟结果。
- `backend/backend/knowledge/grounding.py:22`：门禁检查 JSON 结构、证据 ID、数字子串及带常见剂型后缀的药品名。没有语义蕴含校验；没有数字的新诊断、否定反转等仍可能通过。有效引用不等于引用支持主张。
- `backend/backend/smart_doctor.py:882`：红旗规则在最终出口检查。建议提前计算并优先返回危险提示，避免提示等待检索或模型超时。
- 当前本机配置：BGE 开、模型 `BAAI/bge-small-zh-v1.5`；OpenCMKG 第二路 RAG 关。结构化 JSON 查表不受这个 RAG 开关影响。
- 当前检索金标 86 例：YAML 26、口语 40、无证据 10、急症 10。覆盖类分母 66。脚本将“期望集合任意一个命中”称为 Recall；有多个必要证据的比较题应单独计算证据完整率，而不能只看任意命中。
- 医学安全金标 14 例：急症升级 3、拒答 3、证据忠实 4、有害误导 4。自动模型判读是风险代理，不是临床有效性证明。

## 官方资料支持的可选方向

1. **混合检索与过滤**：Elastic 官方支持全文 + 向量检索及 RRF。项目已有基础，优先补实体、字段、来源、版本过滤。采用设计不意味着需要部署 Elasticsearch。[官方文档](https://www.elastic.co/docs/solutions/search/hybrid-search)
2. **Adaptive-RAG**：按问题复杂度选择无检索/单次/多步策略。原论文包含无检索模型作答；医盾仅借鉴策略选择，医学事实仍须来自资料或规则。[NAACL 2024 论文](https://aclanthology.org/2024.naacl-long.389/)
3. **Corrective RAG**：判断检索证据质量并触发修正。医盾可在库内改写检索一次，仍不足则澄清/拒答；不直接照搬开放网页搜索。[原论文](https://arxiv.org/abs/2401.15884)
4. **Contextual Retrieval 与层级检索**：补充片段所属实体和背景，或命中子片段后取相关父级内容。医盾优先使用结构化字段生成上下文，避免 LLM 生成医学事实；父级回取也须字段白名单和长度预算。[Anthropic](https://www.anthropic.com/research/contextual-retrieval)、[Haystack](https://docs.haystack.deepset.ai/docs/automergingretriever)
5. **有预算的多查询检索**：Azure 文档明确说明复杂问题可拆成并行子查询，并增加延迟；LLM 查询规划标为 preview。医盾先用确定性比较模板拆成 2—3 个子问题，预算是拟议设计，未验证。[官方文档](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-overview)
6. **GraphRAG / LightRAG**：适合实体关系或跨资料综合。微软 global search 使用社区报告与 map-reduce，资源开销高。医盾已有三元组派生关系，应先复用可核验的一两跳关系，不能把症状相关疾病数当患者患病概率。[GraphRAG](https://microsoft.github.io/graphrag/query/overview/)、[LightRAG EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.568/)
7. **Late interaction / 新嵌入模型**：Qdrant 支持 ColBERT 多向量并提醒速度与存储成本；Qwen3 提供 0.6B 等嵌入模型。两者仅作为离线消融候选。此前精排效果差，不能不经评测就重新加回。[Qdrant](https://qdrant.tech/documentation/fastembed/fastembed-colbert/)、[Qwen3](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
8. **逐主张忠实度评测**：Ragas 将忠实度定义为回答主张能否由上下文支持。可作为离线自动评测，中文医学高风险样本仍需人工专业复核。[指标说明](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)

## 哪些问题走什么路径

| 问题 | 主路径 | RAG/生成条件 |
|---|---|---|
| 本人最近检验值、处方用药记录 | 身份验证 → 准入/AST审计 → SQL | 核心事实不用向量检索；通用解释用审核资料，保留个人记录边界 |
| 明确疾病的已收录事实字段 | 精确实体 → 字段查表 | 直接返回，必要时受证据约束改写 |
| 口语症状、疾病别名不清 | 别名优先；必要时语义候选 | 多个相近实体则澄清，不能强制 top1 当诊断 |
| 跨条目的通用知识问题 | 字段/实体/来源过滤 → 混合 RAG | 证据充分才生成 |
| 两个疾病比较、复合问题 | 保留多个实体 → 子问题查表/检索 → 覆盖核验 | 只有覆盖各比较项才生成；部分不足明确分项说明 |
| 统计多少人、按时间排序 | 经权限审计的 SQL 聚合 | 不用相似文档估计精确数字 |
| 急症信号 | 确定性规则优先 | 不等待检索再给提示；知识可后续补充 |
| 库内无依据 | 一次库内纠正或澄清 | 仍无依据则拒答，不让模型补医学事实 |

## 建议实施顺序

### 第一阶段：路由和证据基础（先做）

- 实体携带规范 ID、子类型、别名来源；禁止子型静默退为父病。父病可作为背景，但明确标记不覆盖子型差异。
- 引入 `lookup / explanation / comparison / personal_record / emergency / unsupported` 等任务区别；保留现有五类业务意图的兼容映射。
- 统一 `Evidence` 字段：entity_id、parent_id、field、source、source_version、review_status、原文、稳定 ID。
- 证据门禁增加实体、字段、单位、否定、子类型等确定性检查；高风险事实先模板呈现。语义验证器只能增加一道检测，不当唯一安全裁决。
- 证据不足细分：实体不清、知识缺失、检索失败、模型不可用。来源标签不能把项目整理资料自动说成医院审核。

### 第二阶段：检索适配（通过基线后逐项做）

- 把长事实卡拆成实体+关系字段的子文档，如 `疾病/检查`、`疾病/症状`，父卡保留稳定 ID。
- 索引文本包含实体名、规范别名、关系名、子类型与现有事实。来源版本作为元数据，不靠重复前缀让质量低的文档获得虚假相关分。
- 根据问题过滤或软提升匹配字段；无法确定实体时不做错误的硬过滤。
- 混合检索 → 去重 → 按必要字段回查父级原文 → 证据包。父级回查必须执行来源及字段白名单，不把药物/治疗等原本排除字段重新偷偷送入生成。
- 比较题分项检索，最多少量子问题与一次纠正；没有依据的比较项明确缺失。固定 top3 改为按证据覆盖与 token 预算选取。
- 保留 BGE-small、BM25、RRF、NumPy 与缓存。换语料、模型或推理后端后重建/校验索引，阈值 0.58 不直接沿用到新模型。
- OpenCMKG 第二路从影子评测开始，按领域或任务灰度启用；不要仅打开环境变量就默认全量加入。

### 第三阶段：验证后才考虑重型模型/框架

- 只有候选召回已找到正确证据但排名仍错，才复测中文精排或 ColBERT。
- 只有现有嵌入在口语等难例上确实不足且资源预算允许，才评估 Qwen3/BGE-M3。
- 只有跨实体、多跳任务有明确需求和真实评测收益，才扩图检索；当前无需整体迁移 Microsoft GraphRAG/LightRAG。

## 对照评测和上线门槛

- 固定基线：当前 YAML hybrid；分别比较 +路由、+字段子文档、+受控 OpenCMKG、+多问题检索。最后单独比较可选嵌入/精排。
- 分离调参与盲测，加入子型比较、否定、口语、错别字、未收录问题、矛盾来源、身份隔离等难例。
- 评价：路由准确率、实体/子型准确率、必要证据完整率、Hit@k/Recall@k（明确公式与分母）、MRR/nDCG、无证据误答、逐主张支持率、拒答适当性。
- 生产指标：检索/生成/总耗时分别统计冷启动和暖态 P50/P95，记录内存、token、模型与索引版本、实际后端及降级原因。
- 没有实测前不承诺提升百分比；没有盲测与专业复核前不声称临床可靠。开源基准分数、工程产品可用性和医盾中文医学效果是三类不同证据。

## 预期可见改变（设计目标，尚未实现）

- 本人记录查询保持直接、精确；身份与审计链路继续可追溯。
- 问“1型和2型怎么区分”能保留两类实体，按有证据的维度比较；缺失维度明确提示需要补充资料。
- 口语问法先给匹配或澄清，而非直接输出泛化引导。
- 回答可指向具体疾病的具体字段，而不只是“参考了某张大卡片”。
- 模型不可用仍能看到已经找到的资料；没有 Key 时目前代码跳过检索，是否调整为可检索的原文浏览模式应作为独立产品变更。
