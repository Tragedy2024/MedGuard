# 检索质量评测报告（金标集 v1）

**日期**：2026-10-04
**被测**：`backend/scripts/eval_retrieval.py` × `backend/tests/data/retrieval_gold.jsonl`
**背景**：2026-09 代码评审要求"检索质量有数据支撑"——0.58 稠密阈值、0.7
OpenCMKG 来源权重此前均为经验值。本报告给出四路配置的对照实测。

## 一、金标集（66 条，四类）

| 类别 | 条数 | 评什么 |
|---|---|---|
| `yaml` | 26 | YAML 已覆盖问法（检验/药品/症状/疾病/科室）——期望条目必须在 top-k |
| `colloquial` | 20 | 口语化 / YAML 未收录（帕金森病、荨麻疹、睡不着…）——测召回扩展 |
| `no_evidence` | 10 | 无关问题（天气、菜谱、股票…）——**必须返回空证据**（宁缺勿滥） |
| `emergency` | 10 | 急症表述——由红旗规则层接管（与检索正交） |

期望名在评测开始时对照语料并集（YAML + OpenCMKG）逐一校验，拼写错误会直接报错。

## 二、四路配置对照（Recall@3）

| 配置 | 总 Recall@3 | yaml 类 | colloquial 类 | 无关拒答率 | 误召回 | 急症检出 |
|---|---|---|---|---|---|---|
| `bm25`（纯 BM25，91 条） | 0.2391 | 0.4231 | **0.0000** | 100% | 0 | 10/10 |
| `yaml_hybrid`（+BGE） | 0.6304 | **0.9615** | 0.2000 | 100% | 0 | 10/10 |
| `ocm_bm25`（+OpenCMKG） | 0.3261 | 0.4231 | 0.2000 | 100% | 0 | 10/10 |
| `full`（BGE + OpenCMKG） | **0.9130** | **0.9615** | **0.8500** | **100%** | **0** | 10/10 |

（Recall@5 与 @3 基本一致，见 `--json` 输出；复跑两轮结果稳定。）

## 三、结论

1. **BGE 稠密检索是 YAML 类的主力**：0.4231 → 0.9615。"睡不着""胸口憋得慌"
   这类口语问法的第一层救援靠它。
2. **OpenCMKG 是开口语长尾的唯一途径**：单独用 BM25 打 1.5 万条语料，
   口语类从 0.0000 → 0.2000；与 BGE 合用时 → **0.8500**（帕金森病、荨麻疹、
   颈椎病等 YAML 未收录条目全部可召回）。
3. **诚实的代价为零**：四路配置的无关问题拒答率都是 **100%、误召回 0**——
   扩召回没有牺牲"宁缺勿滥"的门控原则。
4. **红线仍在**：急症 10/10 由红旗规则层确定性检出，与检索无关；
   OpenCMKG 只贡献事实召回，药物/治疗字段未进入检索文档。

## 四、决策门（阶段 2 的验收标准）

> 计划约定：OpenCMKG 提升 Recall ≥5pt 且误召回不放大 → 才讨论把
> `MEDGUARD_RAG_OPENCMKG` 转默认开。

**数据结论：通过**（full vs yaml_hybrid：0.6304 → 0.9130，+28pt；误召回 0 → 0）。

**当前建议：代码默认仍保持关**（演示确定性优先），理由：
- 语料质量等级不同：OpenCMKG 为"学术研究、未经临床审核"（许可与质量
  标注详见 README「数据集怎么用」），默认开需要扩大金标后再评估"医学误导率"；
- 开关是环境变量，答辩/演示现场一条 `MEDGUARD_RAG_OPENCMKG=1` 即可启用，
  本报告就是启用时的数据依据。

## 五、复现方式

```bash
cd backend
python scripts/eval_retrieval.py --config bm25|yaml_hybrid|ocm_bm25|full
python scripts/eval_retrieval.py --all        # 四路对照（子进程，避免配置串扰）
```

注：`--all` 会在某个子进程发生降级（如 BGE 加载偶发失败回退 BM25）时，
把 `[rag]` 日志透传到 stderr——首轮曾出现一次该情况，重跑即稳定，
这本身也是"故障自动降级"设计的现场验证。
