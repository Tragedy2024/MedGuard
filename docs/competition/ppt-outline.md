# 半决赛 PPT 大纲（6 分钟汇报）

> **硬约束**：不得出现学校名称、指导教师姓名、校徽等暗示标识。
> 页数建议 12–14 页；每页只讲一个意思，图表优先于段落。
> 时间分配：问题 30s / 机制 90s / 演示 150s / 证据与开源 60s / 边界 30s。

## Slide 1 · 标题

- 医盾 MedGuard：让 AI 查询在医院边界内发生
- 一句话：在 Agent 和数据库之间，加一道无法被说服的执行点
- 不要放学校/导师/校徽；可放项目 Logo 或纯文字

**视觉**：深色背景 + 一张“Agent → 审计 → 数据库”的极简示意。

## Slide 2 · 问题：中间结果没人审计

- 自然语言 → 多步查询计划 → 子查询结果进模型上下文
- 列掩码管输出，不管中间结果
- 行级权限管“合法查到的”，不管“送进模型”
- 事后过滤召回率低，且破坏查询功能

**视觉**：三段链路图，中间结果处打一个红色问号。

## Slide 3 · 现有防线的边界

| 防线 | 管得住 | 管不住 |
|---|---|---|
| 列掩码 | 最终列 | 中间子查询 |
| 行级权限 | 能读哪些行 | 数据被送进模型 |
| 事后过滤 | 已泄露内容 | 离开边界之前 |
| 提示词防御 | 常见话术 | 换 Agent / 注入 / 混淆代理 |

**一句话**：问题不在“模型听不听话”，而在“执行点有没有裁判”。

## Slide 4 · 核心机制：两层模型

- 层一：身份准入（病患必须绑定本人）——常规授权，不是创新
- 层二：执行前静态审计（零 LLM / 零查库）
- 审计—执行哈希绑定
- L0–L3 降级与 Rule A/C 改写
- 引用监视器三属性：完全中介、防篡改、可验证

**视觉**：两层漏斗 + “审计器：无提示词 / 不查库 / 输出确定”。

## Slide 5 · 层二审计做了什么

- sqlglot AST 静态分析
- 列级：free / controlled / blocked
- 跨域：临床 × 费用个人级 JOIN 禁止
- 派生信息流：聚合/别名/表达式追踪来源
- 输出：违规事件、改写日志、降级等级

**视觉**：一页真实事件的截图（3 条事件 + 改写前后 SQL）。

## Slide 6 · 审计—执行绑定

- 审计后对最终 SQL 做规范化 SHA-256
- 执行器只收到最终一条 SQL
- 执行前再次计算哈希
- 不一致 → 根本不执行
- 报告留痕：decision_id / 计划哈希 / 执行哈希 / 时刻

**视觉**：哈希链条图：审计 SQL → SHA → 执行器 → 比对 → 执行/拒绝。

## Slide 7 · 智慧医生：事实与解释分开

- 本人记录：同一套层一 + 层二
- 疾病/症状：OpenCMKG 派生事实表
- 检验/用药：医院审核 YAML
- 解释：RAG 证据 + 模型转述
- 急诊：红旗规则层，模型无权决定紧急程度

**视觉**：四象限：医院主库 / 医院审核知识库 / 开源数据集 / AI 智能导诊，
分别标注“事实/解释”。

## Slide 8 · RAG 与证据门禁

- BM25 + BGE + RRF，元数据过滤
- 低于阈值返回空证据，不硬凑 top-k
- 模型只能转述证据，输出 claims + evidence_ids
- 普通代码校验：证据 ID / 数字 / 药品名
- 失败 → 原始证据或确定性模板，不 500

**视觉**：检索 → 证据包 → 模型 → 门禁 → 展示/回退 的流水线。

## Slide 9 · 数据与开源管线

- 演示业务库：固定 seed、307 行、SSA 逐列标注
- OpenCMKG：固定版本 + SHA-256、CSV 解析、精度优先清洗、关系映射
- 派生：疾病事实卡 / 症状→科室 / 检索文档
- 受限数据不随仓库分发；合成数据开箱可跑
- 一条命令本地生成完整知识

**视觉**：原始三元组 → 清洗 → 事实表/检索文档 的数据流；
旁边放 `prepare_demo_data.py` 命令。

## Slide 10 · 演示证据：双令牌矩阵

| 问题 | 医护 | 病患 |
|---|---|---|
| 我上次的血糖是多少 | — | L0 放行 |
| 统计各科室接诊量 | L0 | 层一拒绝 L3 |
| 糖尿病患者产生了多少费用 | L2 / 3 事件 | 层一拒绝 |
| 导出患者基本信息核对表 | L2 / 1 事件 | 层一拒绝 |

配合指标条：**LLM 调用 0 / 数据库访问 0**。

**视觉**：矩阵表格 + 指标条截图。

## Slide 11 · 评测证据

- 后端 444 项测试通过；前端 52 项 e2e 断言通过
- 检索金标 86 条；66 条四路对照：BM25 0.239 → +BGE 0.630 → 全量 0.913
- 无关问题拒答率 100%，误召回 0（该评测集）
- 医学安全四维 14 例（风险代理，非临床验证）
- 热查询 P50 约 30ms；审计层 <20ms（历史数据）

**视觉**：一张“证据墙”：测试数、Recall 柱状图、指标条。

## Slide 12 · 开源合规

| 资源 | 边界 |
|---|---|
| 自主代码 | MIT |
| 前期审计引擎 | 团队前期论文成果，明确披露 |
| MAC-SQL | 不再分发源码 |

| Jev | 可选服务，默认仅 3 条合成问句 |

**一句话**：不把第三方数据包装成“医院审核知识”。

## Slide 13 · 诚实的边界与路线图

- 不是医疗器械，不提供诊断/处方
- 不防御小样本聚合推断
- OpenCMKG 未经临床复核
- LLM 失败率未统计；演示依赖缓存
- 下一步：真实 HIS 接入、并发/多数据源测试、更多对抗性测试

**视觉**：左右两栏“已做到 / 还没做到”。

## Slide 14 · 收尾

- 医盾不是让模型更听话，而是让它在关键执行点上没有发言权
- 开源仓库 / 在线 demo / 联系邮箱（不放学校信息）
- 谢谢，欢迎提问

**视觉**：一句话 + 二维码/链接（可选）。

## 答辩准备

- 每个数字都要能说出“怎么测的、在什么数据上、不是什么”；
- 不要把 Jev / RAG 说成核心卖点；核心是审计机制与可验证的产品闭环；
- 被问“创新性”时，用“审计位置前移 + 零 LLM + 哈希绑定 + 证据门禁”四点回答；
- 被问“为什么不用现成方案”时，回到“中间结果/执行前计划”这个空白；
- 被问“临床可靠性”时，主动说边界，不硬撑。
