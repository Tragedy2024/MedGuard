# 6 分钟演示脚本（半决赛视频）

> 目标：在 6 分钟内让评委看到“问题—机制—证据—边界”，不要做成产品功能罗列。
> PPT 与视频中**不得出现学校名称、指导教师姓名、校徽**等标识。
> 视频里不要出现 `.env`、API Key、真实患者数据或内部地址。

## 0. 录制前检查（按顺序）

```bash
# 1) 后端依赖与测试
cd backend
pip install -r requirements.txt
python -m pytest -q                     # 期望：后端测试全绿（以最终回归结果为准）

# 2) 完整知识（可选，但推荐）
python scripts/prepare_demo_data.py --download --proxy http://127.0.0.1:7897
python scripts/prewarm_rag.py           # 期望：status=full, 首次约 1–2s

# 3) 前端构建 + e2e
cd ../frontend
npm run build
MEDGUARD_PYTHON=<python> npm run e2e    # 期望：e2e 全绿（前端 e2e 待最终回归确认）

# 4) 启动单端口演示
cd ..
./start_demo.sh                         # 或 start_demo.bat
# http://localhost:8000
```

- 账号：`patient / medguard`、`doctor / medguard`、`admin / medguard`；
- 演示前先在浏览器登录一次，确认页面不空白；
- **断网演练一次**：演示路径使用预置问题与缓存，不依赖网络；
- 录屏软件先试录 10 秒，确认字号、鼠标、终端日志可读；
- 准备一个“备份录屏”，现场只播放，不临时排障。

## 1. 时间轴与逐镜头

### 0:00–0:35｜问题：中间结果从未被审计

画面：README 首页 / 架构图。

旁白：

> 大模型要参与查询，数据就必须进它的上下文。而 Agent 拆出来的中间结果——
> 那些用户永远看不到、却要送进模型推理的子查询结果——从来没有被审计过。
> 这里就是数据离开医院边界的地方。医盾在 Agent 和数据库之间，
> 加一道无法被说服的执行点。

### 0:35–1:25｜病患：本人血糖，事实与解释分开

操作：

1. 登录 `patient / medguard`（患者端只有一个输入框「智慧医生」）；
2. 在智慧医生输入：**“我上次的血糖是多少”**。

期望画面：

- 路由徽标：**本次走 医院主库**（服务端 `route=personal_record`）；
- 院内数据：`血糖 6.3 mmol/L`；
- 解读：**“偏高（空腹血糖受损）”**；
- 建议：医院审核知识库文案；
- 来源分别标注“医院主库 / 医院审核知识库”。

旁白：

> 患者端只有一个输入框。服务端先用本地确定性规则判断这是本人记录，
> 再走层一准入和层二审计；模型不参与数据读取，也不决定能不能查。
> 解读来自医院审核知识库的数值分档，不是模型自由发挥。

### 1:25–2:05｜疾病知识：Jev 可选公开问句分类（可跳过）

操作：

1. 在同一个输入框继续输入：**“甲状腺结节是咋回事”**。

期望画面：

- 路由徽标：**本次走 知识库**（服务端 `route=knowledge`；患者无需切换页面）；
- 标题：**关于「甲状腺结节」**；
- 条目：普外科、常见症状、常用检查；
- 来源：OpenCMKG（未经临床复核）或“合成演示数据（非临床）”。

旁白：

> 同一个输入框，服务端自动把问题改路由到知识库。只有本地规则完全没识别、
> 且问句精确命中白名单时，才调用 Jev 做公开问句分类；它不接触患者记录，
> 也不生成医学事实，更不参与路由或数据访问判定。没有 Key 时自动关闭，
> 不影响主线。

**如果网络抖动导致 Jev 超时**：直接跳过，改问“我想了解帕金森病”，
用数据集事实卡展示同一能力。不要把 2.5 秒等待剪进视频。

### 2:05–2:45｜症状导诊：给候选，不给“诊断”

操作：输入 **“这几天一直睡不踏实”**。

期望画面：

- 路由徽标：**本次走 知识库**（`route=knowledge`，症状导诊）；
- 识别为“睡眠障碍”；
- 就诊科室候选：精神科 / 神经内科 / 中医综合；
- 文案明确“根据知识图谱中相关疾病的科室分布，仅供参考”。

旁白：

> 症状到科室是两跳图关系，不是患者患病概率；给候选而不是单一结论。

### 2:45–4:05｜核心：医护跨域查询，三条违规被拦

操作：

1. 退出，登录 `doctor / medguard`；
2. 在**可信问答（查询控制台）**选择：**“糖尿病患者产生了多少费用”**；
3. 展开“违规事件”“SQL 改写前后”“指标条”。

期望画面：

- 层一放行（医护令牌）；
- 层二事件 **3 条**：
  - `blocked_column_in_select`：`clinical_records.diagnosis_name`；
  - `column_needs_aggregation`：`billing.amount`；
  - `cross_domain_personal_join`：`clinical_records × billing` 个人级 JOIN；
- 降级 **L2（意图变更）**；
- 改写 1 条 / 2 行日志：
  - 移除 `diagnosis_name`；
  - 将 `amount` 包进 `AVG()`；
- 结果：`SUM(amount) = 129155.41`（当前 seed 下）；
- 指标条：**LLM 调用 0 / 数据库访问 0**。

旁白（重点，放慢）：

> 这不是提示词防御。审计器没有提示词、不访问数据库、输出确定，
> 所以它不能被说服、不能被提示注入绕过。执行器只会拿到审计通过的那条 SQL，
> 而且它的哈希必须和审计产物一致——不一致根本不执行。

### 4:05–4:35｜层一：病患执行前拒绝

操作：登录 `patient`，在**智慧医生（唯一输入框）**输入
**“得这个病的有多少人”**。

期望画面：

- 路由徽标：**本次走 已拒绝**（服务端 `route=general_query`；层一拒绝后
  徽标转为“已拒绝”）；
- 固定文案：**“该查询涉及其他患者信息，无法提供。”**
- 无计划、无结果表、无审计事件（拒绝发生在审计之前）；
- 患者导航中没有查询控制台入口；同一输入框、同一 API 都走层一；
- 页面给出明确的边界文案，而不是含糊的“查不到”。

旁白：

> 服务端先把问题路由到通用查询，但**路由不等于放行**：通用查询仍要过层一
> 准入和层二审计。层一不是本项目的创新，但它是安全演示的对照组：
> 该拒绝的查询不审计、不执行、不留结果。
>
> 可选对照：在同一个输入框先问“心内科有哪些医生”，它会自动路由到通用查询
> 并正常返回——放行与否由层一和策略决定，不由“患者问了什么类型的问题”决定。

### 4:35–5:20｜开源与数据：可复现的边界

画面：架构图 / `prepare_demo_data.py` / `THIRD_PARTY.md`。

旁白：

> 项目自主代码是 MIT；OpenCMKG 只限学术研究，所以仓库不分发原始或派生数据，
> 只开放清洗、转换、索引和评测脚本。新克隆自带合成演示数据，开箱能跑；
> 需要完整知识时，一条命令下载固定版本、校验 SHA-256、本地生成。
> 第三方模型、数据、服务都在 THIRD_PARTY 里写清来源、版本与许可证。

### 5:20–6:00｜证据、边界、路线图

画面：测试输出 / 评测表 / 边界清单。

旁白：

> 后端自动化测试全绿；前端构建与端到端回归按提交前检查清单复跑
> （以最终回归结果为准）。检索有金标评测，医学安全有风险代理评测，
> 延迟和内存有验收数据。
> 但我们不把检索召回率说成医学正确率，不把合成数据说成临床资料，
> 也不防御小样本聚合推断。下一步是把真实 HIS 接入、并发与多数据源测试补齐。

收尾一句：

> 医盾不是让模型更听话，而是让它在关键执行点上**没有发言权**。

## 2. 不建议放进视频的内容

- 长时间的模型调用等待、npm install、BGE 首次下载；
- 真实患者数据、真实医院库、内部地址、API Key；
- “我们用了 DeepSeek / RAG”作为卖点——卖点是审计机制与产品闭环；
- 任何未经验证的“提升 X%”“准确率 Y%”；
- 学校/导师/校徽标识。

## 3. 现场答辩备用问答

| 问题 | 回答要点 |
|---|---|
| 这不就是提示词防御吗？ | 审计器零 LLM、不查库、输出确定；换宿主 Agent 检测率不变，不能被提示注入绕过 |
| 为什么不用现成的 SQL 防火墙？ | 现成方案多按列/行权限；本作品审计的是**执行前的多步计划与中间结果** |
| RAG 会不会编？ | 模型只转述证据；证据 ID/数字/药名由普通代码逐字校验，失败回退原始证据 |
| OpenCMKG 可商用吗？ | 不可以；仓库不分发数据，只开放脚本；演示用合成数据或本地生成 |
| 真实医院能接吗？ | 有数据源注册表与就绪门禁；真实 HIS 接入和多数据源测试是下一步 |
| 为什么用 Jev？ | 可选的公开问句分类，不接触患者数据、不参与路由、不决定访问权限；失败自动回退，不是核心依赖 |
| 患者怎么知道该查本人记录还是通用数据？ | 她不需要知道：服务端本地确定性规则自动路由到本人记录 / 通用查询 / 知识库；路由只负责分流，不授予数据权限 |
| 患者还能进查询控制台吗？ | 患者导航里没有查询控制台，她只有一个输入框「智慧医生」；医生与管理员保留可信问答（查询控制台）。越权问法在同一个输入框里被层一执行前拒绝 |
| 你们的创新点是什么？ | 审计位置前移 + 零 LLM 审计 + 审计—执行绑定 + 证据门禁，四者组合成可验证的引用监视器 |
