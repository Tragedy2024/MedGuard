# 故事版演示脚本（给评委）

> 用法：把这份脚本放在原有 6 分钟技术演示之前/之中，按时间轴串起来。
> 原有 `demo-script.md` 是“技术镜头版”；这份是“故事版”。两者可以二选一，
> 也可以把这里的开场、转场、收尾嵌入技术版。

## 故事主线

**一个入口，两个故事，三层证据。**

- **一个入口**：患者在「智慧医生」里只有一个输入框；问题由**服务端本地
  确定性规则**自动路由到本人记录、通用查询或知识库。医生与管理员保留
  「可信问答（查询控制台）」。大模型负责“翻译”和“表达”，不决定数据访问，
  真正读库的是经过安全审计的 SQL。
- **两个故事**：
  - 患者：从“网上搜不到可信答案”到“每个结论都有出处”；
  - 医生：从“等报表、找信息科”到“实时查、按身份查、按安全策略查”。
- **三层证据**：来源（数据/知识从哪来）→ 审计（执行前拦了什么）→
  绑定（执行的就是审计通过的那条）。

一句话给评委：

> 我们不是让模型更会聊天，而是让 AI 进入医院，但不让数据离开边界。

## 逐字稿

### 0:00–0:50｜开场：一个入口，两个场景

> 各位评委，先想象两个每天都在医院发生的场景。
>
> 一位患者拿到化验单，想知道“我的血糖正常吗”。她打开手机搜索，看到的是
> 互相矛盾的说法；问通用大模型，得到的是一段听起来很确定、却不知道从哪来
> 的回答。
>
> 一位医生坐在诊室，想知道“今天各科室接诊了多少人”。他需要的是医院主库里
> 此刻的真实数据，不是一份昨天的报表。
>
> 这两个问题看起来完全不同，但在我们的平台上，患者只需要**一个入口**：
> 「智慧医生」里的一个输入框。
>
> 她不必先判断“这是本人记录、全院统计，还是医学知识”。**服务端用本地
> 确定性规则**把问题路由到本人记录、通用查询或知识库，并在回答里说明本轮
> 去向。路由发生在模型之前；**Jev 和大模型都不决定数据访问权限**。
>
> 医生和信息科则保留「**可信问答（查询控制台）**」一级工作台：同样的
> NL → 查询计划 → 层一准入 → 层二审计 → 哈希绑定执行。
>
> 所以这个平台后面有**两条链路**：一条通向医院数据库，通用查询与本人记录
> 都要经过审计；一条通向经过审核的医学知识库。大模型在这里不是数据库的
> 钥匙，而是**翻译和表达**；真正读库的，是经过安全审计的 SQL。
>
> 对患者，它降低的是**理解成本**；对医生，它降低的是**查询成本**。
> 接下来，我们用两个操作，看看这个入口背后发生了什么。

**画面**：登录页/角色选择；不要停留太久。可以放一张“患者/医生”双角色示意。

### 0:50–1:30｜患者 A：数据来自医院，解读来自知识库

操作：登录 `patient` → 智慧医生 → 输入 **“我上次的血糖是多少”**。

评委看到：

- 血糖 **6.3 mmol/L**，标签 **“偏高（空腹血糖受损）”**；
- 路由徽标显示**本次走 医院主库**（服务端 `route=personal_record`）；
- 来源分别标注 **“医院主库”** 与 **“医院审核知识库”**；
- 状态 **“结构化资料”**；
- 展开 **“查看本次查询（经医盾审计）”**，看到 SQL；
- 点击 **“查看本次安全报告”**，进入报告页。

> 她看到的是 6.3，偏高。这里有三件事同时发生：数据来自医院主库；
> 解读来自医院审核知识库的数值分档；模型没有参与取数。
>
> 她展开“查看本次查询”，可以看到经过审计的 SQL；点“安全报告”，
> 可以看到这次访问留下的记录。整个过程她只用了「智慧医生」一个输入框，
> 没有切换系统，也没有选择“查询模式”——服务端自动判定这是本人记录，
> 再交给层一/层二审计。
>
> 这就是患者端的第一个变化：她不用自己判断哪个网页可信，系统把
> “数据”和“解释”分开，并且都标出来源。

**注意**：如果现场报告存储不可用，就停在 SQL 展开，不要展开报告链接；
不要现场排障。

### 1:30–2:10｜患者 B：有证据才回答，没证据就承认

操作 1：输入 **“糖尿病和高血压有什么区别”**。

评委看到：

- 路由徽标显示**本次走 知识库**（服务端 `route=knowledge`）；
- 状态 **“证据约束生成 · 2 条依据”**；
- 每条依据带 **出处、开源数据/医院审核资料、核心/扩展资料、匹配分、版本、许可**；
- 答案文字是模型改写的，但事实可回查。

操作 2：输入 **“糖尿病为什么会发生”**。

评委看到：

- 标题 **“换个问法试试”**；
- 状态 **“证据不足”**；
- 没有任何医学断言。

> 同一个输入框，换成知识问题，服务端自动改走知识库——她不需要切换页面，
> 也不需要自己选择“查询模式”。系统不是让模型凭记忆回答，而是先去检索证据，
> 再把证据讲给她听；每条事实都能回到来源、版本和许可。
>
> 如果知识库没有证据，比如“糖尿病为什么会发生”，系统会明确说
> 资料不足，而不是让模型补一段听起来合理的解释。
>
> 所以患者不需要成为检索专家，也不需要判断哪个网页可信；她只需要问，
> 系统负责“路由到正确的链路”和“有出处、不编造”。

**说法边界**：不要说“我们的知识比通用大模型绝对更权威”。
说“我们的答案更可核对：有来源、有版本、有许可、无证据不生成”。
这比空泛的“更可信”更难被评委追问倒。

### 2:10–2:40｜医生 A：实时查，不用等报表

操作：登录 `doctor` → **可信问答（查询控制台）** → **“统计各科室接诊量”**。

评委看到：

- 结果：内分泌科 **20**、呼吸科 **13**、心内科 **16**、消化内科 **20**、
  神经内科 **19**、骨科 **16**（当前演示库）；
- 降级 **L0**，0 个安全事件；
- 指标条 **LLM 调用 0 / 数据库访问 0**（审计阶段）。

> 再看医生。他问“统计各科室接诊量”。这不是一份离线报表，也不是模型
> 估算；是经审计的 SQL 直接读医院主库。医生不用等信息科导报表。
>
> 这里说的“实时”，不是把数据复制到平台再同步；而是查询直接读医院主库。
> 平台不保留一份可被模型访问的离线副本。演示环境用固定种子的仿真库，
> 接入真实 HIS 时查询路径不变。

**说法边界**：如果评委问“你们真的实时同步了吗”，如实说：
“演示库是仿真数据；产品设计是经审计的只读查询直接读业务库，不是复制一份
离线数据给模型。” 不要硬说已经对接了真实医院。

### 2:40–3:40｜医生 B：能查，但不能多带

操作：**可信问答（查询控制台）** → **“糖尿病患者产生了多少费用”** → 点进安全报告。

评委看到：

- 降级 **L2（意图变更）**；
- **3 个安全事件**：
  - 禁止列：`clinical_records.diagnosis_name`；
  - 费用未聚合：`billing.amount`；
  - 跨域个人级 JOIN：`clinical_records × billing`；
- **SQL 改写前后对比** + 改写日志；
- 结果 `SUM(amount) = 129155.41`；
- 指标条 **0 / 0**。

> 他还可以问一个更复杂的问题：“糖尿病患者产生了多少费用”。
> 这是一个跨域问题：临床记录和费用结算属于不同安全域。
>
> 平台给了他统计结果，但在执行前拦下了 3 个风险：禁止列、未聚合的费用、
> 跨域个人级 JOIN。审计器没有提示词、不访问数据库，输出确定；所以它不能
> 被提示注入说服。
>
> 这就是医生端的第二个变化：他不用写 SQL，也不用找信息科；但平台也不会
> 因为“他是医生”就把个人级数据随便带出去。

**转场**：

> 如果病患想借“得这个病的有多少人”看别人呢？

### 3:40–4:05｜边界：病患越权，执行前拒绝

操作：登录 `patient` → **智慧医生（唯一输入框）** →
输入 **“得这个病的有多少人”**。

评委看到：

- 路由徽标显示**本次走 已拒绝**（服务端 `route=general_query`；层一拒绝后
  徽标转为“已拒绝”）；
- 固定文案 **“该查询涉及其他患者信息，无法提供。”**
- 无计划、无结果、无审计事件；
- “被拒绝的查询不进入执行阶段”；
- 患者导航中没有查询控制台入口；同一输入框、同一 API 都走层一。

> 注意，这不是按钮隐藏；即使绕过界面直接调 API，层一也会在执行前拒绝。
> 解析不了就拒绝，fail-closed。
>
> 患者不需要理解“本人记录/通用查询”的区别，服务端确定性路由替她分类；
> 但**分类不等于放行**——通用查询仍要过层一和层二。路由只决定走哪条链路，
> 不授予数据权限，也不由 Jev/大模型决定。
>
> 所以医生得到的是“查得快、带不走”的数据；医院得到的是“能统计、但不越界”
> 的能力。

### 4:05–5:05｜三层证据：来源、审计、绑定

画面：安全报告页 + 导出 JSON + 指标条；可切到管理员“安全策略”页一秒钟。

> 这两类用户，看起来在用一个产品，背后其实是三层证据。
>
> 第一层是**来源**：医院主库、医院审核知识库、开源医学知识图谱，各自标注
> 来源、版本、许可和审核状态。
>
> 第二层是**审计**：在 SQL 执行前，按列级、跨域、派生信息流做静态审计；
> 违规就改写或降级。
>
> 第三层是**绑定**：执行器只执行审计通过的那条 SQL，执行哈希必须和审计
> 哈希一致；报告里能看到 decision_id、计划哈希、执行哈希。
>
> 所以患者端的可信，不是“模型更聪明”，而是“每个结论都能核对”；
> 医生端的安全，不是“界面藏得好”，而是“执行前就被拦住”。

**可选手势**：点“导出完整记录”，不展开 JSON，只让评委看到下载动作；
JSON 里的字段放在 PPT 附录。

### 5:05–5:35｜工程与开源：不是 PPT 架构

画面：PPT 一页（或 CI 页面）。

> 这套东西不是 PPT 里的架构：后端测试全绿；前端构建与端到端回归按

> 本地生成，不把受限数据提交进仓库。

## 可选第三幕：信息科管理员——管得住（45 秒）

> 现有故事是“患者 + 医生”。第三个最该补的是**信息科管理员**：它正好把前端
> 看不到的后端工作，变成可审查、可回看的界面。放在医生故事之后、“三层证据”
> 之前；时间紧时可压成 30 秒，只讲安全报告 + 安全策略。

### 0:00–0:10｜转场

> 前面两个故事里，患者和医生看到的都是结果。现在换一个视角：信息科。

### 0:10–0:25｜安全报告：这次查询到底发生了什么

操作：登录 `admin` → 安全报告 → 打开医生刚发起的
**“糖尿病患者产生了多少费用”**。

评委看到：

- L2、3 个安全事件、SQL 改写前后、改写日志；
- 指标条 **LLM 调用 0 / 数据库访问 0**；
- 点 **“导出完整记录”**，看到 `decision_id`、`plan_hashes`、
  `executed_hash`、`executed_at`。

> 这不是一张结果表，而是一份回执：哪条子查询被拦、哪一列被移除、
> 哪条 SQL 真正执行。执行哈希和审计哈希对得上，说明执行的正是审计通过的那条。

### 0:25–0:35｜安全策略：规则不是藏在代码里

操作：安全策略 → `regional_health` → `clinical_records`。

评委看到：

- `id_card`、`diagnosis_name`：blocked；
- `severity`、`findings`、`impression`：controlled；
- `billing.amount`：controlled；
- 跨域规则：`clinical_records × billing` 个人级 JOIN 禁止。

> 信息科不需要读代码，也能逐列审查“什么能出、什么不能出”；
> 审计器就是按这份策略做静态分析。

### 0:35–0:45｜数据源与账号：能不能用，先看门禁

操作：数据源 → 就绪状态；用户管理 → 患者账号绑定 `P001`。

评委看到：

- 演示库“兼容模式”与未标注列的提示；
- 真实数据源在严格模式下未标注即拒绝启用；
- 患者账号与本人编号绑定；报告按账号隔离。

> 数据源没标全，不允许启用；账号没绑本人，不允许查。
> 这两道门禁在 AI 之前，比任何提示词都硬。

### 0:45–0:55｜收束

> 患者看得懂，医生查得快，信息科管得住。
> 第三类用户不是来用 AI 的，是来**管住 AI** 的——这就是医院敢让 AI 进来的原因。

## 三个可以用的类比

1. **一个入口 = 医院总服务台**：患者只有一个窗口，把问题递进去；分诊台按
   本地确定性规则把她引到本人病历、通用查询或知识库。分诊规则不交给大模型；
   医生则走「可信问答」工作台，窗口能看什么，由身份、令牌和安全策略决定。
2. **RAG = 只允许引用馆藏文献的图书馆员**：不能凭记忆编，只能把找到的
   资料讲给你听；找不到就说没有。
3. **医盾 = SQL 出发前的安检员**：不是等数据出门再查，而是在 SQL 出发前
   检查它想带什么。

## 说法边界（很重要）

| 不要说 | 建议说 |
|---|---|
| “患者有两个入口/两个系统” | “患者只有一个输入框「智慧医生」；医生与管理员保留可信问答（查询控制台）” |
| “路由由 Jev/大模型决定” | “路由由服务端本地确定性规则完成；Jev/大模型只做分类、翻译和表达，不决定数据访问权限” |
| “大模型直接访问医院数据库” | “大模型负责翻译和表达；真正读库的是经审计的 SQL” |
| “我们实时同步了医院数据” | “产品设计是经审计的只读查询直接读医院主库；演示库是仿真数据” |
| “我们的知识库绝对权威” | “医院审核知识库 + 标注审核状态的开源知识图谱；每个结论可追溯” |
| “比通用大模型可信得多” | “与通用大模型最大的区别是：答案有来源、无证据不生成、可核对” |
| “模型不会出错” | “模型只负责改写；证据 ID、数字、药品名由普通代码校验” |
| “我们已经对接了真实 HIS” | “演示环境是仿真库；真实 HIS 接入是下一步，查询路径与审计链路不变” |

## 失败预案

| 如果 | 就 |
|---|---|
| Jev 超时/无 Key | 跳过 Jev，改问“我想了解帕金森病”；不要把等待剪进视频 |
| RAG 未加载/网络抖动 | 先说“当前演示环境降级为 BM25/仅原始证据”，再展示证据卡片 |
| LLM Key 不可用 | R1 改为“仅展示原始证据”；S1/S2/L1 完全离线可跑 |
| 报告页打不开 | 用导出 JSON 或 PPT 里的报告截图替代 |
| 演示库数据变化 | 不说具体数字，改说“当前演示库”；关键事件与改写不变 |

## 一页纸的评委带走

> **一个入口**：患者只有一个输入框「智慧医生」，服务端确定性路由到本人记录、
> 通用查询或知识库；医生与管理员保留可信问答（查询控制台）。  
> **两个故事**：患者看得懂、信得过；医生查得快、带不走。  
> **三层证据**：来源可追溯、审计在执行前、执行与审计哈希绑定。  
> **一句话**：不是让模型更会聊天，而是让 AI 进入医院，但不让数据离开边界。
