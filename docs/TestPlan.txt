--------------------------------------------------------------------------------
一、怎么跑（命令速查）
--------------------------------------------------------------------------------

后端（conda 环境 medguard）

    cd MedGuard/backend
    python -m pytest tests/ -q            # 全量，约 29 秒，250 项
    python -m pytest tests/test_demo_queries.py -v    # 只看演示数据校验（阻塞性）

前端

    cd MedGuard/frontend
    npx tsc -b                            # 类型检查（不用 tsc --noEmit，见下）
    npm run visual                        # 视觉核查，截图到 ../.visual-out/

两个前端服务

    后端  conda activate medguard && cd backend && python -m uvicorn backend.main:app --port 8000
    前端  cd frontend && npm run dev      # http://localhost:5173

> 注意：`npx tsc --noEmit` 在本项目**静默什么都不检查**——根 tsconfig.json 是
> solution 文件（files: []），不含源文件。必须用 `tsc -b`。

三、前端校验
--------------------------------------------------------------------------------

1) 类型检查

    npx tsc -b        # exit 0 为通过

   契约类型由 openapi.json 生成（src/api/types.ts），业务代码经
   src/api/models.ts 取用。**契约一变，这里就报错**——这是有意为之。

   重新生成：
       curl -s http://localhost:8000/openapi.json -o openapi.json
       npx openapi-typescript openapi.json -o src/api/types.ts
       npx tsc -b

2) 端到端回归核查（**断言式**，30 项）

    npm run e2e        # 失败即 exit 1；BASE_URL 未指定且无服务时，自己起一个再停掉

   与下一节视觉核查的区别就在"断言"二字：visual 只截图 + 收报错，**给人看**；
   e2e 判定通过/失败，**给机器判**。它把后端 pytest 里守着的产品声明
   搬到**界面层再验一遍**——在此脚本之前，界面上渲染成什么样是没人管的。

   【API】双令牌矩阵 7/7（准入 / 降级等级 / 事件数 / 有无结果）
          层一拒答文案**逐字**匹配「该查询涉及其他患者信息，无法提供。」
          拒绝时 plan 为空、无结果集
          7/7 条 llm_calls=0 且 db_access=0
          报告按账号隔离（医护读患者的报告 → 404；本人读 → 200）
   【界面】放行路径渲染出结果表 · 拒绝路径渲染出拒答文案且无结果表
          **拒绝后给出可问清单**（不能只留一句拒答让用户猜）·
          **智慧医生的追问入口在首轮之后仍在** ·
          **RAG 检索来源渲染**（用路由 mock——AI 路径要配 Key 才走得到）·
          **多轮上下文**（断言第二轮请求确实带上了上一轮的 intent/entity）·
          指标条显示两个 0 · 安全报告页渲染 · 无控制台报错

   指定已有服务（例如 Vite 开发服务器）：
       BASE_URL=http://localhost:5173 npm run e2e

   > 脚本自身做过**反向验证**：故意改错一个期望值后确实变红、exit 1。
   > 一个不会变红的测试网等于没有网。

3) 视觉核查（16 个用例，用系统已装 Chrome，不下载浏览器）

    npm run visual        # 截图到 ../.visual-out/，并收集控制台报错
                          # 默认打 5173（Vite 开发服务器）；单端口演示请加
                          # BASE_URL=http://localhost:8000
                          # （npm run e2e 的默认值是 8000，两者不一致，见下）

   用例                                      覆盖
   --------------------------------------  ------------------------------------
   00-login                                 登录页（品牌区 + 机制演示 + 表单）
   01-scope-doctor                          可查范围（医护）
   02-scope-patient                         可查范围（病患，**/scope**）

   04-policy                                安全策略逐列审查

   05-forbidden                             **越权访问**：医生直接敲 /policy

四、演示缓存（demo/query_cache.json，11 条）
--------------------------------------------------------------------------------

缓存的是**计划**不是答案——命中后照样走层一准入与层二审计。

问法                          步数  令牌       来源      说明
--------------------------  ----  --------  --------  --------------------------
我上次的血糖是多少              1  patient   preset    本人血糖，放行 L0
医生给我开的药怎么吃            1  patient   preset    本人用药，放行 L0
我的影像报告怎么说              1  patient   preset    本人影像，放行 L0
心内科有哪些医生                1  patient   preset    不涉及患者表，放行 L0
得这个病的有多少人              1  patient   preset    **层一执行前拒绝 L3**
统计各科室接诊量                2  staff     preset    干净查询 L0（对照组）
糖尿病患者产生了多少费用        2  staff     preset    **跨域** 3 违规 L2
按诊断结果分类统计患者数        2  staff     preset    **派生** 2 违规 L2
导出患者基本信息核对表          1  staff     preset    **禁止列** 1 违规 L2
我治疗了哪些患者                1  staff     llm       自由提问生成的（额外）
全院各科室的门诊量分别是多少    2  staff     llm       自由提问生成的（额外）
--------------------------  ----  --------  --------  --------------------------

> **为什么 9 条预置计划要灌进缓存**：实测同一句「糖尿病患者产生了多少费用」，
> 走预置按钮是 L2/3 违规（计划用跨域 JOIN），走自由提问是 L0/0 违规（模型自己
> 选了更安全的子查询写法）。同一个问题两种结果，而且模型倾向选安全写法，
> **自由提问的演示效果普遍太平淡**。这 9 条自由问法与预置库文案完全相同，
> 本就该拿到同一份计划。
>
> 命中缓存**不绕过审计**：实测两条路径均为 L2 / 3 违规 / 1 改写。

演练方式：改完缓存后跑第三节的视觉核查，逐条确认降级等级与违规数符合上表。

五、端到端验收：双令牌矩阵（设计文档 §6.5）
--------------------------------------------------------------------------------

这一组是**产品主张的证明**：同一套界面、同一个问题，两类令牌给出不同结果。

问题                        令牌      预期              实测（2026-09-15）
------------------------  --------  ----------------  ----------------------
我上次的血糖是多少        病患      放行 + 层二通过    L0  违规 0  结果有
心内科有哪些医生          病患      放行（不涉患者表）  L0  违规 0  结果有
得这个病的有多少人        病患      **层一执行前拒绝**  L3  结果无
统计各科室接诊量          医护      放行（对照组）      L0  违规 0  结果有
糖尿病患者产生了多少费用  医护      放行 + 层二跨域拦截  L2  违规 3  结果有
按诊断结果分类统计患者数  医护      放行 + 层二派生拦截  L2  违规 2  结果有
导出患者基本信息核对表    医护      放行 + 层二禁止列    L2  违规 1  结果有
------------------------  --------  ----------------  ----------------------
                                                        7/7 全部符合预期

配套断言（不可放宽）：

  · 层一拒绝时 plan == []、result == null，文案必须是
    「该查询涉及其他患者信息，无法提供。」（固定产品文案，前端不改写）
  · 指标条 llm_calls == 0 且 db_access == 0
    （这是「零 LLM、零查库」安全声明的可验证形式）
  · 报告页能列出历史、详情含 payload、导出带 Content-Disposition: attachment
  · 报告**按账号隔离**：医生与患者各自只看到自己发起的查询；
    越权读/导出别人的报告 id 一律 404；不带 token_type 的请求 422

七、已知未覆盖（不是遗漏，是刻意的）
--------------------------------------------------------------------------------

1. 前端无单元测试
   只有 tsc -b（类型）与 npm run visual（视觉 + 控制台报错）。
   React 组件的逻辑分支没有自动化覆盖。
   风险：改组件时靠视觉核查兜底，覆盖不到交互分支。

2. 无浏览器端到端测试
   没有 Playwright 断言式 E2E（现在的脚本只截图 + 收报错，不做断言）。
   双令牌矩阵是**人工核对**的，不是 CI 化的。

3. 无性能测试
   「审计 < 20ms」来自算法层实测，产品侧没有持续的耗时断言。
   指标条上的 elapsed_ms 是真实读数但没有阈值告警。

4. 无并发测试
   FastAPI 是同步路由，SQLite 单写者。并发提问下报告写入的竞争未测。

5. 无多数据源测试
   当前只有 regional_health 一个演示库。接入真实数据源时，
   config.PATIENT_TABLES、`_discover_datasources()` 的枚举逻辑需要新测试。

6a. 真实模型路径**从未被自动化测试覆盖过**
   智慧医生的 AI 兜底测试全部把 `_call_llm` 打桩，LLM 翻译测试也不联网，
   所以整套测试**不需要 openai 也不需要网络**。
   注（2026-09-21 核实）：本条原先记有"`medguard` 这个 conda 环境**没装
   openai 与 func_timeout**，故漏打桩的用例会假绿"——**前半句已不成立**：
   实测两个包都在（openai 3.14.1 / func_timeout 4.3.5）。
   但**风险本身仍在**，只是机理变了：当前未设 `OPENAI_API_KEY`，漏打桩的
   用例会走 `ai_triage` 的"无 Key 早返回"分支而通过——**仍是假绿**。
   所以"每个走 AI 的用例都显式打桩"这条纪律必须保留，不能因为包装上了就放松。
   真机上一次都没跑过。

6. 模型路径的稳定性未量化
   LLM 翻译会遇到输出格式不符（实测碰到过；已靠输出规整大幅缓解，
   但**失败频率没有统计过**——不要引用具体数字）。
   缓存兜住了演示路径，**未命中时的失败率是未知的**。

7. 安全边界未做渗透式验证
   「病患令牌无法触及任何涉他患者数据」靠的是层一准入 + 算法层审计的
   单元测试，没有对抗性测试。已知边界见会议记录 §11：
   本引擎不防御小样本聚合推断（如罕见病计数）。
