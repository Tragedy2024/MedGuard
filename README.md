# 医患信息数据服务云平台

**安全引擎：医盾 MedGuard**

让不会写 SQL 的医护人员和病患，用大白话查到权威准确的医院数据，
并保证查询的**中间过程**不泄露患者信息。

`FastAPI` · `React 19` · `TypeScript` · `SQLite` · `sqlglot`

</div>

---

## 这是什么

一个面向医院场景的数据查询平台。医生和病患**用中文提问**，答案**直接来自医院主库**——
大模型只负责把问题翻译成 SQL，不生成任何答案内容。

> **一处限定**：患者的「智慧医生」在**知识库未覆盖**的问法上会调模型生成*解读*
> 与*建议*文案。那是文字解释，不是数据——院内数据仍然只来自主库，模型碰不到。
> 而且它**必须逐块标注来源**：「医院审核知识库」与「AI 智能导诊」分开，
> 绝不把模型生成的内容盖成人工审核章。

但它真正在做的事在另一侧：

> 大模型要参与查询，数据就必须进它的上下文。
> 而 Agent 拆出来的**中间结果**——那些用户永远看不到、却要送进模型推理的子查询结果——
> 从来没有被审计过。**这里就是数据离开医院边界的地方。**

列掩码管不住它（中间结果不是"输出"），行级权限管不住它（那些数据是"合法查到的"），
事后过滤管不住它（召回率 0–16.7%，且会破坏查询功能）。

医盾在**执行之前**对查询**计划**做静态审计，补上这个位置。

## 机制

```
用户提问（自然语言，携带令牌）
    │
    ▼
┌─ 翻译 ──────────────────────────────────────────────────────┐
│ 自然语言  ──▶  查询计划 [{id, description, sql}, …]          │
│ 缓存优先，未命中才调 LLM。LLM 只翻译，不生成数据答案。       │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
            ┌──【层一】准入检查 ──┐
            │ 这个令牌能发起       │──拒绝──▶ 固定文案，不查库、不执行
            │ 这个查询吗？         │
            └──────────┬──────────┘
                       │ 通过
                       ▼
            ┌──【层二】医盾审计 ★ ─┐
            │ 零 LLM · 零查库       │
            │ sqlglot 纯 AST 静态分析│
            │ 列级 / 跨域 / 派生信息流│
            └──────────┬──────────┘
                       │ 改写后的计划 + L0–L3 降级
                       ▼
                   执行 ──▶ 医院主库 ──▶ 结果
```

**层一**是常规授权——"你不该问这个"，**不是本项目的创新**。
**层二**才是——"你能问，但这条计划会多带数据出去"。

把两者混为一谈，就会把常规授权包装成研究成果。这个区分必须讲清楚。

### 为什么"零 LLM"是安全属性，不是性能优化

| | 提示词防御 | 医盾 |
|---|---|---|
| 换一个宿主 Agent | 只降 1.4–9 倍，**不清零** | 检测率不变 |
| 能否被提示注入绕过 | **能** | **不能** |
| 能否被当作混淆代理去查库 | 可能 | **不能** |

审计引擎没有提示词、不访问数据库、输出确定——
三条合起来就是经典安全里的**引用监视器（Reference Monitor）**：
完全中介 + 防篡改 + 可验证。

> 一句话：在 Agent 和数据库之间，加一道**无法被说服**的执行点。

## 快速开始

### 环境

- Python **3.10+**（实测 3.13 / conda 环境 `medguard` 为 3.12）
- Node **20+**（实测 24）

### 一键启动（演示用，推荐）

```bash
./start_demo.sh              # Git Bash / macOS / Linux
start_demo.bat               # Windows 双击
```

两个脚本做同一件事：找解释器 → 验依赖 → 必要时构建前端 → 起服务 → 开浏览器。
加 `--lan` 还能让手机或另一台电脑通过局域网 IP 打开。

**只有一个进程、一个端口**（`http://localhost:8000`）。后端顺带托管前端构建
产物，前后端**同源**——浏览器不产生跨域预检，换端口、用局域网 IP、前面加反代
都不会撞 CORS。演示现场因此少一个会翻车的环节。

> 前端**单独**跑（带热重载）时仍走 `npm run dev` + Vite proxy，见下面两节。

### 后端

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn backend.main:app --reload --port 8000
```

首次启动会**自动生成演示库**（5 张表、291 行虚构数据），无需手动操作。

```bash
curl http://localhost:8000/api/health          # {"status":"ok","algo_engine":"available",…}
curl http://localhost:8000/api/datasources     # 应返回 regional_health
```

### 前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Vite 已配好 proxy，把 `/api` 转发到 `8000`，**无需处理跨域**。

### 演示账号

| 账号 | 密码 | 身份 | 能进哪些页 |
|---|---|---|---|
| `admin` | `medguard` | 医院管理员（信息科） | 数据源 / 安全策略 / **用户管理** / 查询控制台 / 安全报告 |
| `doctor` | `medguard` | 医护人员（医生001·心内科） | 可查范围 / 查询控制台 / 安全报告 |
| `patient` | `medguard` | 病患（患者001） | 可查范围 / 查询控制台 / 安全报告 |

> **身份决定能进哪些页面，令牌决定能查到什么数据**——两者正交。
> 医护与病患的页面完全相同，差别只在令牌；患者额外拥有「智慧医生」（可信就医助手，登录后默认页）——那是患者视角的主入口，其余页面照常。这正是演示矩阵成立的前提。
> 身份**不可在界面上随手切换**，必须退出后重新登录——
> 对一个以安全为卖点的产品，"能随便切身份"本身就是可信度问题。

**这三个账号存在后端**（平台元数据库的 `users` 表，口令是 PBKDF2 哈希，
不是明文），登录由 `POST /api/auth/login` 判定并**签发带 HMAC 签名的令牌**，
所有收令牌的端点都会验签。管理员登录后可在「用户管理」页建新账号——
医院里开号是信息科的活，所以**没有自助注册**；非管理员调用建号接口返回 403。

### 关于 API Key（可选）

```bash
cp .env.example .env      # 填入 OPENAI_API_KEY
```

**不填也能完整演示。** 演示路径全部走预置查询与本地缓存——
离线、确定性、毫秒级返回。Key 只影响"打字问一个全新问题"这一个场景，
**与安全审计无关**：审计环节零 LLM、不读这个配置。

## 演示动线：双令牌矩阵

同一套界面、同一个问题，**两类令牌给出不同结果**。这是权限隔离最直观的证明。

| 问题 | 医护令牌 | 病患令牌（层一判定） |
|---|---|---|
| 我上次的血糖是多少 | —（该角色无此问法） | ✅ 放行 + 层二通过 |
| 心内科有哪些医生 | ✅ 放行 | ✅ 放行（不涉及患者表） |
| 统计各科室接诊量 | ✅ 放行（对照组，L0 / 0 事件） | ❌ **层一执行前拒绝** |
| 糖尿病患者产生了多少费用 | ✅ 放行 + **层二跨域拦截**（L2 / 3 事件） | ❌ **层一执行前拒绝** |
| 按诊断结果分类统计患者数 | ✅ 放行 + **层二派生拦截**（L2 / 2 事件） | ❌ **层一执行前拒绝** |
| 导出患者基本信息核对表 | ✅ 放行 + **层二禁止列**（L2 / 1 事件） | ❌ **层一执行前拒绝** |
| 得这个病的有多少人 | —（该角色无此问法） | ❌ **层一执行前拒绝**（L3 / 无结果） |

> **关于"该角色无此问法"**：示例问题下拉按令牌类型过滤——病患看不到
> 医护专属的问题，反之亦然。若绕过下拉直接以 API 发起，路由会先行返回
> `403 该令牌无权使用此查询`。这是可点击演示之外的一层更早的、更省成本的守卫；
> **层一准入始终是最终裁决**（上表"病患令牌"一列即层一的判定结果，
> 对自由提问路径同样成立）。
>
> **可点击的层一演示是「得这个病的有多少人」**——它在病患的下拉里，
> 点下去就能看到执行前拒绝。

层一拒绝时返回**固定文案，不做任何改写**：

> **「该查询涉及其他患者信息，无法提供。」**

不假装"查不到"——含糊的失败会让用户反复换问法试探。明确告知边界是可解释性，
且对所有涉他查询统一措辞，避免通过错误信息差异反推数据存在性。

### 界面上必须能被当作证据的三件事

1. 指标条的 **`LLM 调用 0 / 数据库访问 0`**——"零 LLM、零查库"的可验证形式
2. **改写前后的 SQL 对比**，哪一列、因为什么、被怎么处理了
3. 报告页可回看的**历史留痕 + 一键导出 JSON**

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 19 · Vite 8 · TypeScript 6 · React Router 7 | 纯展示层，不直接读数据 |

| 契约 | OpenAPI → `openapi-typescript` | 后端一改，前端**编译报错** |

## 关键设计决策

| 决策 | 理由 |
|---|---|
| **算法层一行不改** | 产品是纯适配器，`import` 即接口契约；耦合点收敛在 `deps.py` 一个文件 |
| **层一与层二分开实现** | 层一是常规授权（非创新），层二才是算法创新 |
| **安全策略每数据源一份，不按角色分** | SSA 描述数据自身的属性，与谁在问无关 |
| **病患令牌全称禁止涉他数据** | "可反推性"不可判定（需知结果基数，而基数要查库）；全称禁止是可判定的 |
| **演示库 SSA 手写而非 LLM 生成** | 标注工具不生成跨域规则；blocked 标签需人工定案 |
| **策略页仅管理员可见** | 那是平台管理职能。与"层二与角色无关"不矛盾——后者说数据属性，前者说谁能改标注 |
| **界面上只用中文业务别名** | 向医生展示 `clinical_records.impression` 只会把产品退回成开发者工具 |
| **缓存计划而非答案** | 命中缓存后照样走层一与层二，安全演示一点不打折 |
| **平台元数据库与业务库分离** | 前者是平台自身状态，后者是被审计对象 |

## 诚实的边界

这一节不是免责声明，是这个项目的可信度所在。

- **翻译准确率是 62–77%，不是 100%。** 这是 MAC-SQL 在 BIRD/Spider 上的公开实测数字
  （`EX`），文档与演示中如实呈现。
- **演示走预置查询与本地缓存**，NL→SQL 那一步不实时调用。
  理由：产品创新点全在审计侧；而模型单次翻译要几十秒，会让视频录制不可控。
  **审计与准入判定 100% 真实**，两条路径实测结果一致（同为 L2 / 3 违规 / 1 改写）。
- **本引擎不防御小样本聚合推断**（如罕见病计数）。这是"可反推性不可判定"的必然结果，
  由层一的全称禁止在病患侧兜底。
- **SSA 是列级标注**，不编码值或行。
- **审计的是"查询计划"这一层**。若 Agent 绕过计划直接执行 SQL，中介就不完整。
- **未标注的列默认放行**（`fail-open`）。所以策略页的"审查状态"不是装饰，
  它对比库中实际列与策略标注，把漏标的列标出来——这是产品层能提供、
  算法层看不见的价值。
- **当前为仿真数据**，非真实医院数据。所有姓名/证件号一律"一眼假"（`患者001`、`TEST-000001`），
  绝不使用看似真实的个人信息。
- **无暗色模式，无隐私政策/服务条款链接。** 医疗数据产品化时应补。

### 已知未覆盖（刻意的）

前端无单元测试、无断言式 E2E、无性能与并发测试、无多数据源测试。
原因与风险见 `docs/TestPlan.txt` 第七节。

### 契约变更流程

`src/api/types.ts` 是生成物，**禁止手工编辑**。业务代码一律从 `src/api/models.ts` 取类型。

```bash
# 1. 改后端 backend/schemas.py
# 2. 重启后端，重新导出与生成
curl -s http://localhost:8000/openapi.json -o frontend/openapi.json
cd frontend && npx openapi-typescript openapi.json -o src/api/types.ts
npx tsc -b          # 有错就是契约对不上——这正是这一步的目的
```

`models.ts` 里的联合类型（`TokenType` / `DegradationLevel` / `EclLabel`）
是**从契约派生**的，不是手写。后端一改取值，前端立刻编译失败——这是有意为之。

`.gitignore` 已配置。特别提醒：**`.env` 含真实密钥**，
误提交后必须立刻去服务商后台吊销换新——删文件是不够的，密钥还留在历史里。

<details>
<summary>算法层的复用方式</summary>

算法层（医盾引擎）**已内置**在 `backend/vendor/nl2sql/`，
拿到文件夹即可运行，无需额外安装。定位顺序：

1. 环境变量 `MEDGUARD_NL2SQL_SRC`
2. **内置** `vendor/nl2sql/src`（默认命中）
3. 相对路径探测（MedGuard 与 NL2SQL 同级时自动命中）
