# PRODUCT.md — 医患信息数据服务云平台（安全引擎：医盾）

> 本文件承载**产品真相**，不承载视觉决策。视觉世界由 DESIGN.md 与 surface brief 拥有。

## 一句话

让不会写 SQL 的医护人员和病患，用大白话查到权威准确的医院数据，
并保证查询的**中间过程**不泄露患者信息。

## 不可复制的机制

医盾引擎在查询执行**之前**，对查询**计划**做静态审计。三条属性都是可验证的：

- **零 LLM** → 没有提示注入面
- **零查库** → 没有困惑代理（confused deputy）面
- **确定性输出** → 可形式化验证

它拦的不是"答案"，而是**中间结果暴露**：子查询 SELECT 了不需要的受控列，
虽不改变最终答案却泄露了信息。列掩码、RLS、事后过滤都拦不住这一类——
前两者管不住"合法查了但要送进模型"的数据，后者召回率 0–16.7% 且破坏功能。

**这是本产品唯一不可被复制的东西，界面必须让它看得见。**

## 用户（三类，权限不同）

| 身份 | 要什么 | 能进哪些页面 |
|---|---|---|
| 医护人员（如 医生001·心内科，工号 S001） | 所辖患者的统计与明细 | 可查范围 / 查询控制台 / 安全报告 |
| 病患（患者001，P001） | 本人病历里的具体答案 | 可查范围 / 查询控制台 / 安全报告 |
| 医院管理员（信息科） | 配置数据源与安全策略、看审计留痕 | 数据源 / 安全策略 / 查询控制台 / 安全报告 |

**身份决定能进哪些页面，令牌决定能查到什么数据**——两者正交。医护与病患的
页面完全相同，差别只在令牌：同一个问题，两类令牌给出不同结果。这是演示的
核心命题，也是这个产品最直观的证明。

## 真实场景

医院走廊、护士站、诊室——屏幕常被侧光照着，用户刚查完房或刚拿到检验单，
想立刻知道一个数。**他们不认识 SQL，也不关心 SQL。** 单次查询的审计耗时
是毫秒级（实测 1–9 ms），而模型翻译一句新问法要 5–20 秒。

## 这个界面必须证明什么

1. **答案来自主库，不是模型生成的。** 让"权威准确"成为可验证的主张，
   而不是宣传语。
2. **中间过程被看见了。** 审计不是一个黑箱结论，而是一份可以逐条回看的证据：
   哪一列、因为什么、被怎么处理了。
3. **零 LLM、零查库是真的。** 指标条上的 `LLM 调用 0 / 数据库访问 0`
   必须醒目到能被当作现场证据。

## 硬约束（不可违反）

- **算法层一行不改**（论文仓库是只读依赖）
- **红 / 琥珀 / 绿是安全语义专用**：层一准入=红（执行前阻断）、
  层二审计=琥珀（改写/降级）、L0=绿（通过）。**绝不用于装饰**，
  包括角色标签、指标数字。
- **界面上只用中文业务别名**，不出现 `frequency` / `clinical_records`
  这类物理名——那会让产品退回成开发者工具（需求分析阶段已否决的形态）
- 演示数据必须一眼假（患者001 / TEST-000001），绝不使用看似真实的个人信息
- **诚实地标注边界**：EX 是 62–77% 不是 100%；不防御小样本聚合推断

## 演示语境

竞赛演示视频。评委与观众会盯着看，会试着问预设外的问题。
离线、确定性、毫秒级返回是演示能不能站住的前提。
